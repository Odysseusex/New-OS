# Развёртывание ArAmir OS для постоянного использования

Этот документ — пошаговая инструкция, как открыть ArAmir OS по ссылке в браузере
(с компьютера, телефона, iPad — с любого устройства), используя бесплатные
облачные сервисы. Никакой новый репозиторий не создаётся — разворачивается
именно этот проект, основная ветка `main`.

## Почему нельзя развернуть прямо сейчас одной командой

Я (Claude) работаю в изолированном временном контейнере без доступа к вашим
личным аккаунтам. Регистрация в облачном сервисе — это ваш email, согласие с
условиями использования, иногда телефон для подтверждения. Это шаг, который
обязан сделать человек, а не ассистент. Поэтому я подготовил весь проект так,
чтобы развёртывание заняло у вас ~20–30 минут по этой инструкции, без
написания кода.

## Архитектура развёртывания

Используются три бесплатных сервиса — каждый лучший в своей задаче:

| Компонент | Сервис | Зачем именно он |
|---|---|---|
| База данных PostgreSQL | **Neon** (neon.tech) | Бессрочный бесплатный план, не удаляется через 30/90 дней, готов для Prisma |
| Backend (API на NestJS) | **Render** (render.com) | Бесплатный Web Service, автоматический деплой из GitHub |
| Frontend (интерфейс на Next.js) | **Vercel** (vercel.com) | Лучшая в мире поддержка Next.js, бесплатный план, без задержек на статике |

**Важно про бесплатный план Render:** если API не получает запросов 15 минут,
он «засыпает», и первый запрос после этого выполняется 30–60 секунд (сервис
просыпается), дальше работает быстро. Это нормальное поведение бесплатного
тарифа, не ошибка. Если это будет мешать (например, вы уже тестируете
платформу с сотрудниками ежедневно), позже можно перейти на платный тариф
Render (от $7/мес) — тогда сервис не засыпает.

## Порядок действий

Порядок важен: сначала база данных → потом backend → потом frontend → потом
возвращаемся в backend и указываем адрес frontend (для безопасности CORS).

---

### Шаг 1. База данных — Neon

1. Зайдите на [neon.tech](https://neon.tech) и зарегистрируйтесь (можно через
   GitHub-аккаунт — быстрее всего).
2. Нажмите **Create a project**. Название — например `bakery-os`. Регион
   выбирайте ближайший к вам (например, Europe).
3. После создания проекта Neon покажет **Connection string** — строку вида:
   ```
   postgresql://user:password@ep-xxxx.eu-central-1.aws.neon.tech/neondb?sslmode=require
   ```
4. Скопируйте эту строку целиком и сохраните — она понадобится на шаге 2.

---

### Шаг 2. Backend — Render

1. Зайдите на [render.com](https://render.com) и зарегистрируйтесь через
   GitHub-аккаунт, в котором лежит репозиторий `keremetAI/repo` (это даст
   Render доступ на чтение репозитория для деплоя).
2. В панели Render нажмите **New +** → **Blueprint**.
3. Выберите репозиторий `keremetAI/repo`. Render найдёт файл `render.yaml`,
   который уже лежит в корне проекта, и предложит создать сервис
   `bakery-os-api` со всеми настройками (команды сборки и запуска уже
   прописаны — трогать их не нужно).
4. В поле **Branch** должна стоять `main` (это ветка по умолчанию — Render
   выберет её сам).
5. Render попросит заполнить переменные окружения, помеченные как «нужно
   ввести вручную»:
   - `DATABASE_URL` — вставьте строку подключения из Neon (шаг 1).
   - `WEB_ORIGIN` — пока оставьте пустым или поставьте `http://localhost:3000`,
     вернёмся к этому на шаге 4.
   - `JWT_SECRET` Render сгенерирует сам — трогать не нужно.
6. Нажмите **Apply** / **Create Web Service**. Начнётся первая сборка — она
   займёт несколько минут: установит зависимости, применит миграции базы
   данных и загрузит демо-данные (те же demo-пользователи, магазины, клиенты,
   что вы видели при разработке — **они сохраняются**, ничего не удаляется).
7. Когда сборка завершится, Render покажет адрес вашего API, например:
   ```
   https://bakery-os-api.onrender.com
   ```
   Сохраните этот адрес — он понадобится на следующем шаге.
8. Проверьте, что API работает: откройте
   `https://bakery-os-api.onrender.com/api/health` в браузере — должно
   появиться `{"status":"ok","service":"bakery-os-api"}`.

**Если сборка упала с `Exited with status 1 while building your code`:**
это общее сообщение Render, точная причина — строкой выше в логах. Самые
частые причины:
- **`DATABASE_URL` не вставлен или вставлен неверно** — шаг применения
  миграций (`prisma migrate deploy`) не может подключиться к базе. Проверьте,
  что скопировали строку из Neon целиком, без лишних пробелов.
- **Несовпадение версии pnpm** — уже исправлено в проекте (файл
  `package.json` фиксирует точную версию через поле `packageManager`), но
  если ошибка про `pnpm`/`lockfile` всё же появится — напишите мне точный
  текст ошибки из логов Render (раскройте красную строку с ошибкой, там будет
  подробность), я поправлю.

---

### Шаг 3. Frontend — Vercel

> **Примечание:** изначально ветка `main` в этом репозитории была почти
> пустой заглушкой (вся разработка шла в отдельной ветке) — из-за этого
> Vercel мог не находить Next.js и показывать пустые поля Root Directory /
> Environment Variables. Это исправлено: `main` теперь содержит весь проект.
> Если вы уже открывали экран создания проекта раньше и видели там
> **Application Preset: Other** — обновите страницу или начните импорт
> заново, чтобы Vercel перечитал актуальный `main`.

1. Зайдите на [vercel.com](https://vercel.com) и зарегистрируйтесь через тот
   же GitHub-аккаунт.
2. Нажмите **Add New** → **Project**, выберите репозиторий `keremetAI/repo`.
3. На экране настройки (Vercel всегда импортирует ветку по умолчанию —
   `main`, менять ничего не нужно):
   - **Application Preset / Framework Preset** должен определиться сам как
     **Next.js**. Если видите **Other** — значит, Vercel ещё не подхватил
     обновлённый `main` (см. примечание ниже).
   - **Root Directory** — нажмите «Edit» и укажите `apps/web`.
   - Остальные поля (Build Command, Install Command, Output Directory,
     Environment Variables) на этом экране можно оставить пустыми/по
     умолчанию — заполним переменную окружения отдельно на следующем шаге.
4. В разделе **Environment Variables** добавьте:
   - Имя: `NEXT_PUBLIC_API_URL`
   - Значение: адрес API с шага 2 **плюс `/api`**, например:
     ```
     https://bakery-os-api.onrender.com/api
     ```
5. Нажмите **Deploy**. Через 1–2 минуты Vercel выдаст постоянную ссылку вида:
   ```
   https://repo-xxxx.vercel.app
   ```
   Это и есть ссылка, по которой вы будете открывать платформу с любого
   устройства — компьютера, телефона, iPad.

   Если сборка упадёт с ошибкой про зависимости монорепозитория, зайдите в
   Settings → Build & Development Settings и переопределите:
   - **Install Command:** `pnpm install`
   - **Build Command:** `cd ../.. && pnpm --filter @bakery-os/shared build && cd apps/web && pnpm run build`

   Это резервный вариант — обычно Vercel справляется с pnpm-монорепозиторием
   автоматически.

---

### Шаг 4. Вернуться в Render и разрешить доступ с вашего домена

Сейчас backend ещё не знает про адрес вашего frontend и будет блокировать
запросы (защита CORS). Нужно это исправить:

1. Вернитесь в Render → сервис `bakery-os-api` → **Environment**.
2. Отредактируйте переменную `WEB_ORIGIN`, вставив адрес из Vercel (шаг 3), без
   слэша `/` на конце:
   ```
   https://repo-xxxx.vercel.app
   ```
3. Сохраните — Render автоматически передеплоит сервис с новой настройкой
   (это быстро, миграции и сборка заново не нужны, но по факту Render всё
   равно пересоберёт — дождитесь зелёного статуса **Live**).

## Что дальше

- **Реальные данные:** когда будете готовы, скажите — заменим демо-организацию
  на вашу настоящую (название пекарни, реальные точки, сотрудники, товары), а
  тестовые записи удалим отдельным шагом, не трогая структуру.
- **Свой домен** (например, `bakery.вашкомпания.kz`): подключается в Vercel
  за 5 минут (Settings → Domains), если появится домен — скажите, подключим.
- **Обновления платформы:** дальнейшая разработка идёт в том же репозитории и
  той же ветке — как только я добавляю новый модуль и делаю `git push`, Render
  и Vercel автоматически передеплоят изменения сами, вручную ничего делать не
  нужно.
- **Если Render-«засыпание» начнёт мешать** — дайте знать, обсудим переход на
  платный тариф (недорого) или альтернативный always-on вариант.
