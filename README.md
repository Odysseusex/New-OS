# Bakery OS

Платформа управления сетью пекарен: продажи, производство, склад, логистика,
финансы, карта города и AI-рекомендации — в едином продукте, независимом от
внешних систем (UMAG, iiko, 1С подключаются как адаптеры поверх единой модели
данных).

## Структура репозитория

```
apps/
  web/      Next.js — интерфейс (на русском)
  api/      NestJS — backend API
packages/
  shared/   Общие типы и роли, используемые web и api
```

## Стек

- **Frontend:** Next.js 14, TypeScript, Tailwind CSS, lucide-react
- **Backend:** NestJS, TypeScript, Passport/JWT
- **База данных:** PostgreSQL 16 + Prisma ORM
- **Монорепозиторий:** pnpm workspaces

## Первый запуск

### 1. Установить зависимости

```bash
pnpm install
```

### 2. Поднять PostgreSQL

Локально (уже настроен кластер `16/main` на порту 5432) либо через Docker:

```bash
docker run --name bakery-postgres -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=bakery_os -p 5432:5432 -d postgres:16
```

### 3. Настроить переменные окружения

```bash
cp apps/api/.env.example apps/api/.env
cp apps/web/.env.local.example apps/web/.env.local
```

### 4. Применить миграции и засеять демо-данные

```bash
cd apps/api
npx prisma migrate dev
npx ts-node prisma/seed.ts
```

### 5. Запустить приложения (в двух терминалах)

```bash
pnpm dev:api   # http://localhost:3001/api
pnpm dev:web   # http://localhost:3000
```

Демо-пользователи (все с паролем `password123`):

| Email | Роль | Доступ |
|---|---|---|
| `owner@bakery.demo` | Владелец | Вся сеть |
| `manager@bakery.demo` | Управляющий точкой | Только «Магазин «Абай»» |
| `cashier@bakery.demo` | Кассир | Только «Магазин «Абай»», может проводить продажи |
| `warehouse@bakery.demo` | Кладовщик | Только «Центральный склад», приёмка/списание |
| `technologist@bakery.demo` | Технолог | Только «Производство №1», рецептуры и задания |
| `baker@bakery.demo` | Пекарь | Только «Производство №1», выполняет задания |
| `driver@bakery.demo` | Водитель | Только назначенные ему маршруты доставки |

**Примечание:** `packages/shared` собирается в обычный JS (`dist/`) и
подключается через `main`/`types` в `package.json` — это нужно, потому что
Node 22 иначе пытается нативно исполнять `.ts`-файлы пакета как ESM и падает
на relative-импортах без расширений. `pnpm install` пересобирает `shared`
автоматически (`postinstall`); после ручных правок в `packages/shared`
запустите `pnpm --filter @bakery-os/shared build` перед перезапуском API.

## Текущий статус

Реализован фундамент платформы и семь «боевых» модулей:

- мультиарендная модель данных (организации → регионы → точки → пользователи);
- аутентификация и роли (11 ролей, от владельца до водителя);
- каркас интерфейса на русском языке со всеми 17 модулями в навигации;
- рабочий модуль **Дашборд**: реальная выручка сегодня/за 7 дней и алерт по
  низким остаткам (кликабельный переход в Склад), плюс структура сети;
- рабочий модуль **Продажи**: сводка выручки, лента транзакций, оформление
  продажи с автоматическим списанием склада;
- рабочий модуль **Склад**: остатки по точкам с подсветкой низких остатков,
  приёмка и списание с указанием причины, журнал движений, номенклатура
  товаров;
- рабочий модуль **Производство**: рецептуры (техкарты) с автоматическим
  расчётом себестоимости и маржи, производственные задания с планом/фактом,
  завершение задания списывает сырьё и приходует готовую продукцию по норме
  расхода — всё в одной транзакции с проверкой достаточности запасов;
- рабочий модуль **Закупки**: реестр поставщиков, заказы на пополнение склада,
  приёмка заказа пополняет остатки той же транзакцией, что и производство/
  продажи — единый склад для всех источников движения товара;
- рабочий модуль **Карта**: интерактивная SVG-карта города по реальным
  координатам точек (без зависимости от внешних картографических сервисов —
  они заблокированы политикой этой песочницы, а как отдельный vendor-агностик
  архитектурно и не нужен), с наложением выручки и алертов по остаткам;
- рабочий модуль **Логистика**: транспорт, многоостановочные маршруты доставки
  с несколькими товарами на остановку; доставка остановки одной транзакцией
  переносит товар со склада точки отправления на склад точки назначения
  (тот же журнал движений, что у продаж/производства/закупок), при доставке
  последней остановки маршрут авто-завершается;
- рабочий модуль **Финансы**: P&L за период (сегодня/7 дней/30 дней/месяц) —
  выручка, себестоимость (из рецептур, с запасным расчётом по средней цене
  закупки для товаров без техкарты), валовая и чистая прибыль с учётом
  расходов; ручной учёт расходов по категориям и точкам; экспорт P&L по
  товарам в CSV (для Excel/1С); честно помечает позиции без данных о
  себестоимости вместо того, чтобы показывать заниженную маржу;
- RBAC-скоупинг по точкам: управляющий точкой/кассир/кладовщик/технолог/пекарь
  видят и меняют данные только своей точки, водитель видит только назначенные
  ему маршруты (независимо от точки), владелец/админ/региональный директор/
  бухгалтер — видят всю сеть, могут фильтровать по точке и одни имеют доступ
  к финансовым показателям;
- остальные модули отображаются как «в разработке» с описанием будущего
  функционала — это осознанное отражение реального прогресса, а не заглушки
  с fake-данными.
